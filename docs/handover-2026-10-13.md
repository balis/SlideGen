## How plugin fixes are made during the test

1. A session in `~/work/lsc-course` logs a defect in `TEST-LOG.md` (file and
   line, symptom, severity) and stops the phase if it is a blocker. It does not
   edit the plugin.
2. A session here reads that log and, when it needs the details, the test
   session's transcript in `~/.claude/projects/-home-ubuntu-work-lsc-course/`
   (`<session id>.jsonl`; `ws ls lsc-course` shows which id is which phase).
   `python3 ~/work/scratch/transcripts/dump.py <transcript> 300` prints one
   readably: messages in full, tool calls and results shortened.
3. Fix and test in a worktree (`ws shell slidegen/fix-<name> --worktree`),
   merge into `slidegen-plugin` only between phases, push, and update the
   defect's status in `TEST-LOG.md`. The test project loads the plugin straight
   from this checkout, so the next session there (or `/reload-plugins`) uses
   the fix, and a change merged during a phase would alter that phase.
4. Where the fix needs a project change (as P1-7 needed collector entries in
   the manifest), make it in `~/work/lsc-course` and commit it there.

## Tried and rejected

- **Sonnet fact-checkers.** Lecture 4 was first checked with Sonnet
  (`decks/bde-v2/lectures/lecture04/workspace/checks-sonnet/`). An Opus
  re-check found 10 more problems, 4 of them major. Fact-checkers stay on
  Opus, and a run that cannot afford its models stops instead of switching.
- **WebFetch answers as evidence.** That compares model-written text with
  model-written text. Every source is downloaded with `sg fetch`, and quotes
  are matched mechanically against the stored text.
- **A date window for the new-developments search.** Decks are re-saved every
  year, so file dates say nothing about content; one reviewed Spark PDF was
  created in 2026 but named nothing newer than 2014. deck-modernize surveys the
  current state of each topic instead.
- **Priorities set by the agent that finds an item.** The finder rated its own
  items and nothing checked the rating. `sg` derives priority from recorded
  criteria (`plugin/references/severity.md`).
- **Checking only volatile claims.** The decks carry no provenance, and the
  rule would have classed "Trino keeps intermediate data in memory" as stable
  because a 2019 paper describes it, skipping the case that motivated the
  review. Claims are selected by rule instead.
- **A 2-of-3 vote on critical findings.** False critical findings come from
  research (a wrong or opinion source), and three checks of the same file
  agree with each other. A critical finding gets a blind second research pass
  and a second check.
- **Locating changes by slide number, and new slides in Markdown.** Numbers
  shift when the author inserts a slide, and Markdown cannot be pasted into
  PowerPoint. Changes are located by title and a text snippet in an annotated
  PPTX copy, and new slides are native slides on the deck's own master.
- **A per-item checklist in deck-modernize.** 33 items for one deck were too
  many to review. A decisions form is planned instead; it is not built.
- **Topic lists from syllabi and textbooks to judge what is new.** They lag by
  years and missed data contracts. field-trends measures an approved panel of
  sources over two 12-month windows.
- **Slide counts guessed in the course plan.** Lecture 1 of bde-v2 came out at
  26 slides. `lectures.slides` in `plan.yaml` and `sg lecture outline-check`
  now hold every lecture to the author's range (50–60 per 90 minutes).
- **Querying Hacker News by the field's name.** "data engineering" mostly
  returned AI launches. Collectors query qualified topic names.
- **`--no-session-persistence` for headless runs.** A resumed run lost the plan
  that lived only in the first run's context.
- **The Write tool for headless prompt files outside the project.** It asks
  for approval. Write them with a heredoc in a sandboxed Bash command.

- The plugin is installed in `~/work/lsc-course` from the local marketplace
  `~/work/slidegen` (project scope). It loads in place from
  `~/work/slidegen/plugin`: all 4 skills and 23 agents appear, and a change
  here reaches the next session there.
- What the sandbox allows, from headless smoke runs in `~/work/lsc-course`
  (logs in `runs/smoke/` there):
  - Bash reaches every host: the user-level `WebFetch(domain:*)` rule feeds
    the sandbox allowlist, so `allowed_domains` is not needed.
  - The sandbox proxy re-signs TLS. `requests` (and so `sg fetch`) trusts it
    through the environment; yt-dlp needs `--compat-options no-certifi`.
  - LibreOffice cannot open its IPC pipe inside the sandbox ("no valid pipe
    path found"). `sg pptx render` works as an excluded command, called with
    absolute paths and a 10-minute Bash timeout.
- Start headless `claude -p` runs from a plain shell in tmux. A `claude`
  started from a sandboxed Bash call has not been tried; it would need to
  write `~/.claude`, which the sandbox does not allow.

  `--max-budget-usd` are API-equivalent estimates.
