EXCERPT (supporting claim:agde:temporal-leak-naive-join:004):
"Feast is able to join features from one or more feature views onto an entity dataframe in a point-in-time correct way. For each row within the entity dataframe, Feast will scan backward in time from the entity dataframe timestamp up to a maximum of the TTL time specified. The last row in the entity dataframe was outside of the TTL window (the event happened 11 hours after the feature row) and also couldn't be joined."

ADDITIONAL CONTEXT — what a naive join does wrong:
The Feast documentation implies the naive join problem: without backward time scanning, a standard SQL equi-join between a transactions table, a customer dimension table, and a labels table (all keyed on customer_id without timestamp constraint) will pick up the latest available customer attributes regardless of whether they were available at transaction time. If a customer's credit tier, lifetime value, or aggregate fraud count was updated after the labeled event, the training row will reflect that updated (future) state rather than the state at prediction time.
